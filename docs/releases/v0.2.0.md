# ProjectFlow v0.2.0

> Publicación: 2026-07-24
> Sprint: 2 — Cotizaciones
> Estado: Aprobado

## Resumen

La versión `v0.2.0` incorpora Cotizaciones como una entidad de negocio versionada que
precede a los Proyectos. El módulo conserva acuerdos aprobados, registra revisiones,
protege el aislamiento entre Organizaciones y genera documentos PDF bajo demanda.

## Funcionalidad

- folio `COT-000001` independiente por Organización;
- Persona asociada con rol Cliente;
- editor de Draft y conceptos;
- cálculo decimal de descuentos e impuestos;
- envío, aprobación, rechazo, expiración y archivo;
- nuevas versiones para cambios comerciales;
- correcciones administrativas auditadas;
- historial completo de versiones;
- PDF por QuoteVersion;
- interfaz web autorizada y modo de solo lectura.

## Datos y despliegue

- Ejecutar `composer install --no-dev --optimize-autoloader`.
- Ejecutar `php artisan migrate --force`.
- Ejecutar `npm ci` y `npm run build`, o desplegar los assets ya construidos según el
  proceso del entorno.
- Mantener `php artisan schedule:run` ejecutándose cada minuto para procesar
  `quotes:expire`.
- La migración agrega `quote_sequences`, `quotes`, `quote_versions`, `quote_items` y
  `quote_version_revisions`, junto con restricciones y triggers multitenant.

## Compatibilidad

- PHP 8.4 o superior.
- Laravel 13.
- MariaDB.
- No expone API pública.
- No convierte todavía Cotizaciones en Proyectos.

## Decisión sobre identidad de la Organización

QuoteVersion conserva el snapshot del Cliente. Para el MVP, los datos de la
Organización incluidos en el PDF se leen desde su información vigente. No se agrega un
snapshot histórico de la Organización en esta versión.

## Calidad

- 90 pruebas y 301 aserciones.
- PHPStan/Larastan sin errores.
- Composer Audit sin vulnerabilidades conocidas.
- Laravel Pint correcto.
- Build de Vite correcto.

## Riesgos conocidos

- La identidad histórica de la Organización puede evaluarse en una versión futura.
- El despliegue debe mantener activo el scheduler de Laravel.
- El Sprint 3 deberá definir la conversión idempotente desde una versión aprobada a
  Proyecto antes de implementarla.
